# Product completion audit — Genesis CAP Growth V1

## Active authoritative loop

World App → World ID → Title acquisition → immutable CAP entitlement → Social → Genesis Journey → Monthly Human Claim → five-winner monthly draw → CAP claim → quarterly eligibility → Wallet → Fairness.

## Closed contradictions

- New Title purchases use 40/38/10/10/2 only; older allocation rows remain versioned history.
- Monthly draws resolve five ordered winners with 55/25/10/6/4 and no replacement.
- Quarterly supersedes annual for new draws; annual names are explicitly legacy-only.
- Monthly Human Claim V2 supersedes daily/fixed-immediate claims.
- Paid scratch is no longer reachable product behavior; historical persistence remains readable.
- Public browser access is verification-only; no alternate wallet, auth, purchase, claim, or ownership path exists.
- Beta demo purchase is explicit, non-monetary, and production-forbidden.
- No peg, APY/yield, cashback promise, CAP/WLD rate, or hard-coded Genesis reward is active.

## Deliberately retained compatibility

- Historical scratch types, rows, RPC, and read parsing remain for migration/history. The active server route is a fail-closed tombstone.
- `ANNUAL_LEGACY`, legacy allocation buckets, and old claim tables remain readable for historical data.
- Phase 3 legacy scratch reserve models remain test-only provenance and do not issue outcomes.

## External gates

Deployment credentials/configuration, Developer Portal setup, World review, external quest verification, final tokenomics, CAP contract integration, real custody/payout, legal/compliance authorization, and independent security review remain outside this implementation branch.
